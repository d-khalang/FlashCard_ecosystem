# Bot architecture refactor

Goal: make the bot core reusable so the Telegram bot and the Mini App become thin
clients of one set of use cases. Work happens on `main` first; the Mini App is then
rebuilt on top of it. Every step is behavior-preserving unless stated.

## Problems (root causes)

| # | Problem | Mini App symptom it caused | Status |
|---|---------|----------------------------|--------|
| 1 | Language is a deployment (one process + database per language), not data | Per-language databases, authority DB, language exchange, two builds | Open |
| 2 | No use-case layer: business logic lives in Telegram handlers; scheduler copies `/get` | Parallel core, `enrolled()` branches patched into handlers | In progress |
| 3 | Services don't own their data: raw `cols` everywhere, several services write `users` | CAS checks, fencing, revisions | Open |
| 4 | A review is not an entity: only scattered flags (`has_pending`, `pending_message_id`) tied to a Telegram message | Attempts, receipts, dispatch tokens, presence | Open |
| 5 | Cards are regenerated by the LLM on every review, never stored | Preparation store, content versions, saved fallback, job queues | Open |
| 6 | Quota is ad hoc: counters on the user doc, limits frozen at import, trial derived from `created_at` | Parallel quota/allowance system, `miniapp_accounting` fencing | Open |
| 7 | Global singletons (`settings`, `i18n`, `TIER_LIMITS`) imported at module level | Runtime-mode explosion, separate runners | Open |
| 8 | Writes are not idempotent (regex de-duplication, no unique index) | `action_id` required on every call | Open |
| 9 | Loose types: `user_id` is `str` or `int`, dicts instead of models, ISO strings compared as text | BSON Int64 session bug | Open |
| 10 | No shared composition root: dispatcher data dict; startup wiring duplicated in `bot.py` | `MiniappRuntime` built its own composition | Open |

## Deferred issues (do not forget)

- **Quota as its own concept (#6).** Callers ask two separate questions:
  `can_generate_card()` then `card_limit()` for the message. Replace with one
  call, e.g. `quota.check_card(user) -> Allowed | Exceeded(limit)`, that owns
  tier limits, the trial and own-key handling.
- **`/get` vs scheduler differences**, pinned by tests and kept for now:
  `user_id` is `int` in `/get` and `str` in the scheduler (#9); `/get` reloads the
  user, the scheduler reuses it; over quota, `/get` tells the user while the
  scheduler skips silently. Decide deliberately, then unify.
- **Duplicated startup** in `bot.py`: `init_telegram_bot` and
  `init_telegram_without_fastapi` build the same services twice (#10).
